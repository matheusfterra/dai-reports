Documentação técnica do workflow EVOPE — Gerador de Relatório de Automação.

1Canais de Entrada #

O workflow aceita arquivos por dois canais independentes. Ambos convergem para o mesmo pipeline de validação e processamento.

CanalNodeQuando UsarResposta
Formulário EVOPE n8n-nodes-base.formTrigger Upload manual pelo usuário final via UI do n8n Resultado enviado por email — sem resposta inline
Webhook Externo n8n-nodes-base.webhook Integração programática — a plataforma EVOPE envia o arquivo automaticamente Responde 202 Accepted imediatamente (async), resultado por email

Fluxo do Webhook (assíncrono)

O webhook retorna resposta imediata para não travar a requisição enquanto o processamento ocorre em background:

fluxo webhook
POST /webhook/evope/gerador
    │
    ├── Webhook (recebe arquivo binário)
    │       │
    │   Preparar Dados Webhook (normaliza estrutura para o pipeline)
    │       │
    │   Responder Webhook ─────────────────► 202 {"status":"processing"} (imediato)
    │       │
    │   Validar Estrutura do Arquivo
    │       │
    │   [pipeline continua...] → Email com resultado

4Conversão de Formatos #

O workflow suporta três formatos. Cada um tem um nó específico de extração, com normalização de encoding para CSV (problema comum com arquivos exportados pelo Windows).

FormatoNóObservação
.xlsx fromXLSX Excel 2007+. Formato preferencial — preserva tipos de dados e encoding UTF-8 nativamente.
.xls fromXLS Excel legado (97-2003). Suportado para compatibilidade com exports de sistemas antigos.
.csv Normalizar Encoding CSV → fromCSV Passa por normalização antes da extração. Detecta e converte Latin-1/Windows-1252 para UTF-8.

5Validação de Estrutura #

Após a extração, o nó Validar Estrutura do Arquivo verifica se os dados têm o formato esperado pelo EVOPE.

VerificaçãoAção se Falhar
Colunas obrigatórias presentesErro → email com lista de colunas faltantes vs esperadas
Arquivo não vazio (pelo menos 1 linha de dados)Erro → email informando arquivo vazio
Tipos de dados coerentesErro → email com diagnóstico da coluna problemática
⚠️ Nó Verificar Erro: É um nó if que bifurca o fluxo. A saída 0 (true) vai para o pipeline de erro; a saída 1 (false) continua o processamento normal.

9Pipeline de Tratamento de Erros #

Quando a validação falha, o workflow não quebra — envia um email de diagnóstico ao usuário com instruções claras.

fluxo de erro
Verificar Erro [SAÍDA 0 = erro detectado]
    │
    Preparar Email de Erro
    │   Inclui:
    │   - Tipo de erro (estrutura inválida / arquivo vazio / encoding)
    │   - Colunas encontradas vs colunas esperadas
    │   - Nome do arquivo recebido
    │   - Instruções para corrigir e reenviar
    │
    Enviar Email de Erro (Gmail)
✅ Design de resiliência: Nenhum erro quebra silenciosamente. O usuário sempre recebe feedback — seja o relatório ou um email explicando o problema.

1. Configuração de Ferramentas — 2 novos parâmetros #

Adicionados dois campos ao nó Set de configuração global para que ajustes de negócio não exijam alteração de código:

CampoValor padrãoFunção

Processar e Agregar Dados compara cada aplicativo/funcionalidade contra esta lista.

2. Processar e Agregar Dados (v2.12) — Entretenimento + Desvio Padrão #

2a — Detecção de Entretenimento

Para cada grupo no loop, verifica se aplicativo ou funcionalidade da linha bate com algum app da lista appsEnt. Campos adicionados ao objeto de grupo:

CampoTipoDescrição
isEntretenimentobooleantrue se o grupo tem uso de entretenimento detectado
percEntretenimentonumber (0–100)% de horas do grupo gasto em apps de entretenimento

2b — Jornada Excessiva via Desvio Padrão (σ)

Após o forEach principal, calcula média e desvio padrão das horas por colaborador. Retorna campo jornadaExcessiva no objeto de saída:

// Objeto jornadaExcessiva no output:
{
  "colaboradores": [
    { "nome": "Marcos Rocha", "horasH": 30, "desvios": "2.0σ" },
    { "nome": "Ana Paula",    "horasH": 26, "desvios": "1.6σ" }
  ],
  "media": 12.2,
  "desvioPadrao": 8.9,
  "threshold": 25.5,   // média + 1.5σ
  "sigma": 1.5
}

Colaboradores com horasH > threshold são incluídos em colaboradores[]. Threshold 0 é ignorado (sem dados).

3. AI Agent — Análise (system prompt) — 3 novas regras #

RegraInstrução adicionada ao prompt
Mínimo de planos de ação OBRIGATÓRIO: planosAcao deve ter MÍNIMO 5 e MÁXIMO 8 itens. Nunca retorne menos de 5 planos de ação.

4. Pipeline Caminhos — Bug LangChain BufferMemory corrigido (3 nós) #

Bug original: AI Agent — Caminhos crashava com "input values have 2 keys, you must specify an input key or pass only 1 key as input" quando o payload não tinha dados de caminhos. O workflow inteiro travava.
NóMudançaMotivo
Preparar Prompt Caminhos Quando links.length === 0, adiciona _semCaminhos: true ao output em vez de passar dadosAnalise completo LangChain BufferMemory não aceita objeto com 2+ chaves como input. Passando apenas 1 campo (_semCaminhos), o agente recebe o item mas sem acionar o bug
AI Agent — Caminhos onError: "continueRegularOutput" (continueOnFail habilitado) Mesmo que o agente falhe internamente, o workflow continua para o próximo nó sem travar a execução
Extrair Análise Caminhos Verifica firstItem._semCaminhos e firstItem.error antes de ler output. Retorna string vazia ('') em caso de erro ou ausência Sem este guard, o nó quebrava ao tentar acessar output de um item com erro ou nulo 
// Extrair Análise Caminhos — lógica de guard:
const firstItem = items[0]?.json || {};
const aiResponse = (!firstItem._semCaminhos && !firstItem.error)
  ? (firstItem.output || firstItem.text || '')
  : '';  // retorna vazio — Gerar HTML Final trata ausência corretamente
